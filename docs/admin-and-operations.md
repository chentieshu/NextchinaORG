# 后台与生产缺口（2026-10-13）

管理入口：`https://tree.teamcn.org/zh-CN/`。使用现有总管理员账号登录。

## 当前后台

- 概览显示数据库中的帖子、新闻、有效评论和用户数量，点选即可进入对应列表；草稿、发布和归档数量分别显示。
- 帖子与新闻支持状态、分类、正文或作者名称筛选，按创建时间稳定分页。列表不下载整篇富文本。管理员的编辑、置顶、锁定、下架/恢复及删除入口直接可见。
- 评论显示当前头像和名称，可以搜索正文、编辑、软删除并进入原讨论。删除父评论保留后续讨论上下文。
- 总管理员独有：用户权限、停用账号、分类管理、全站设置、操作记录、服务监控。子管理员可管理全站内容，但不能修改这些站级设置。普通用户不能发布新闻。数据库策略/受控函数执行权限校验，隐藏按钮不是安全边界。
- 总管理员可以管理其他人的帖子、新闻及评论。内容归属与 ID 不提供重写操作；自己的最高管理员身份也不会被普通权限下拉框降级，以免锁死管理入口。

## 分类

`omni_categories` 是唯一分类来源，论坛侧栏、新闻筛选、编辑器和后台使用相同资源。

创建时填写固定网址标识（小写字母开头，可含数字与短横线，最长 40 字符，不可使用 `all`）、五语言名称、排序和启用状态。排序数字小的在前，相同数字按网址标识排序。创建后固定标识不可改变，名称可以更改。

停用分类会从新发帖选择和公共筛选中移除，但保留历史内容及原网址。仍可编辑原分类中的旧内容；新内容及改换分类必须选启用分类。删除只允许未被任何内容引用的分类，外键阻止误删。最多 100 个分类；记录所有分类变更。

分类和全站设置保存携带 `updated_at`。有另一页面先保存时返回冲突，不覆盖远端，并保留当前输入。全站设置提供“放弃编辑并重新载入”。分类冲突后可取消并重新打开当前分类。

## 状态管理的实际边界

已经具备：身份/权限隔离、账号变更后重建后台、请求取消与序号检查、稳定分页、私有收藏清理、失败/离线提示、重复提交保护、草稿本地恢复、服务端时间戳并发检查。点赞/收藏分页读取，避免超过 API 单页上限后遗漏。旧的账号刷新请求不会撤销期间已经完成的互动。

继续共用现有 Context 和各模块请求状态，没有引入第二套状态库或重复用户表。回到页面/网络恢复时刷新；聚焦刷新做短时合并。

这不是完整实时系统：其他设备的内容、关注、计数变化需要重新读取；没有 Supabase Realtime 或跨页内容广播。离线写作只是本地草稿，不会后台自动发布。大规模互动仍会在身份刷新时按页读取个人互动集合，未来应改为按当前可见内容查询状态，并配合按用户隔离的服务端缓存。列表和计数不是一个数据库事务快照，外部写入后可能短暂不一致。文章并发修改提供冲突提示，没有版本历史或自动合并。

## 服务监控

媒体 Worker 新增 `GET /v1/admin/metrics`。先调用 Supabase 验证 Bearer 用户，再查询实时用户角色及停用状态；仅 `super_admin` 可访问。数据库统计 RPC 同样独立校验角色。浏览器仅发送自己的登录令牌；没有 `service_role`、管理 PAT 或 R2 密钥。

| 数据 | 来源与口径 |
|---|---|
| 数据库大小 | `pg_database_size(current_database())`，不含 WAL 等额外磁盘占用 |
| 应用表及索引大小 | public 下 omni 表与私有应用表的 `pg_total_relation_size` 汇总 |
| 当前数据库连接数 | `pg_stat_database.numbackends`，不是最大可用连接配额 |
| 近 24 小时上传额度记录 | 私有上传预留账本，失败上传也可能占预留额度，不能当实际文件数 |
| 媒体对象数量和字节 | R2 binding 对 avatars/ 与 content/ 前缀实际分页遍历，不含内部监控缓存 |
| 媒体服务状态 | 该 Worker 成功完成此次经身份验证的请求，不代表 Cloudflare 全平台状态 |

R2 缓存 5 分钟，单次最多 20 页且限制扫描耗时；超过边界显示“部分扫描”，数值是已扫描量。并发上传下多页列表不是原子快照。显示采集起止时间；错误显示失败，不伪造零值。监控每用户每分钟 4 次，独立于上传限流。R2 List 本身属于计费请求，目前手动刷新，没有持续后台轮询。缓存保存在私有桶 `ops/` 下，公共图片路由无法访问。

尚未接入 Cloudflare 官方流量、CPU、错误率、历史趋势、部署历史、费用，也没有 Supabase CPU/内存/出站流量及费用。这些信息通过提供商控制台链接查看。当前 Cloudflare connector 查询账户 token 权限组返回 Unauthorized，因此没有创建或假称已配置长期凭据。

后续接入 Cloudflare 官方监控可使用只读服务端 token：当前账户的 `Account Analytics Read`，如需要 Pages 部署再加 `Pages Read`；站点级 HTTP 指标还需仅 teamcn.org zone 的 `Analytics Read`。将其存入 Worker secret，固定账户、bucket、script/project，不能接受浏览器传任意 GraphQL。当前代码不读取此 token，也未虚设一个可用配置入口；接入时需要新增实际采集器和测试。

Supabase 完整监控需要独立服务端 Metrics API 采集。不要为了简易面板把 secret key 放入网页。R2 官方 bandwidth 数据集排除小于 100 KiB 的传输，尤其不能把头像流量当作精确总流量。

## 仍需补齐的生产工作（优先级）

1. **发布前联调**：真实用户完成 GitHub / X 授权、账户绑定与解绑，以及 Resend 邮件登录、改邮箱、密码恢复的收件闭环；现有浏览器测试拦截这些写请求，不替真实用户授权或发信。Google 登录曾由站长确认，新域名仍应完成真实回归。Supabase 泄露密码保护仍有原有 advisor 提示。
2. **社区治理**：举报入口及处理队列、屏蔽/静音、防垃圾注册与恶意重复内容控制、申诉、账号删除/数据导出流程。已有数据库节流与媒体上传额度，尚不能替代完整滥用防护。
3. **运维可靠性**：备份/恢复演练、R2 保留与孤儿图片清理策略、异常告警及历史指标、错误追踪。当前监控为按需查看，不会自动报警。不能声称备份恢复已演练。
4. **内容分发与规模化**：每帖服务端 SEO 和分享图、全文搜索索引、大列表游标分页、按可见内容获取互动状态、查询与高并发容量测试。
5. **社交体验**：跨设备实时同步、回复/关注通知、消息系统及编辑历史。是否需要私信可按产品范围后续决定。

## 验证

新增 PGlite 测试实际执行全部迁移，覆盖分类新增/停用/删除、被引用类别保护、五语言校验、设置并发冲突、总管理员管理他人内容与角色隔离。Worker 测试覆盖身份拒绝、停用账号、R2 多页与缓存、来源失败不显示零。浏览器使用隔离的假后端测试分类同步、筛选、冲突输入保留、监控错误和手机布局；不在生产发布测试帖子。
